# k8s/image-roster.txt — the deploy roster (ORB-362).
#
# One line per image the pipeline promotes and pins. (The build list is still
# stl-verify/Makefile's docker-release-all: a roster line needs a matching
# release target, or verify-ecr-images.sh fails the stamp with a missing-image
# list.)
#
#   <kind> <name> <alias> [<alias> ...]
#
#   kind   service — its own ECR repo, stl-sentinel<env>-<name>, tagged <sha>
#          cronjob — the shared stl-sentinel<env>-cronjob repo, tagged <name>-<sha>
#                    (cmd/cronjobs/<name>, or a one-off backfiller built the same way)
#   name   the image: the repo suffix (service) or the tag prefix (cronjob)
#   alias  every `image:` name a k8s/base/*/ manifest uses for it. Several bases
#          share one binary and differ only by env (per-chain watchers, per-DEX
#          indexers, per-exchange order books): list each alias. `-` = no alias
#          (built and promoted, but pinned only by a hand-maintained overlay such
#          as k8s/overlays/*/bootstrap/).
#
# Names and aliases are lowercase [a-z0-9-] and unique across the file; column
# alignment is cosmetic. Removing or re-homing an image is the one sanctioned
# hand edit of a generated block: change the roster AND delete the stale entry
# from each overlay's images block in the same PR (the bot only rewrites the
# block after merge, so the PR check would otherwise flag the leftover entry).
# A re-home leaves the alias unpinned in the merge commit until that rewrite —
# the same brief ImagePullBackOff window as a first rollout.
#
# scripts/deploy/render-overlay-images.sh renders this into the `images:` block
# of k8s/overlays/{staging,prod}/kustomization.yaml; the deploy bot rewrites that
# block wholesale on every deploy, and deploy.yaml promotes exactly these names
# to prod. Never edit the generated blocks. Adding an image = one line here plus
# its base manifests and `resources:` entry; the next deploy pins it.
# `#` starts a comment; blank lines are ignored.
